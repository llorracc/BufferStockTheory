# `concepts/`

YAML "concept atlas" for the paper. Each `<id>.yml` is one economic
concept with its defining equation, an English gloss, typed
cross-references to other concepts, and source anchors back into
`BufferStockTheory.md`. The atlas exists to make the paper's math
legible to AI/RAG tooling: a curated, machine-readable graph of the
named scholarly objects (conditions, theorems, definitions) and how
they relate.

The atlas currently holds **42 authored concepts** (verify, do not
trust this frozen number: `python3 tools/concepts_freshness.py`, which
asserts the concept-YAML count equals the count in
`_ai/concepts/index.md`). They arrived in two tiers:

- **13 exemplar concepts** (added 2026-05-03) — the original
  hand-curated seed set.
- **29 new concepts** (added 2026-06-22) — a breadth pass. These 29
  are **pending author review** (see "Review status" below).

`13 + 29 = 42`. To check which tier a concept belongs to:

```
git log --diff-filter=A --format=%cs -1 -- concepts/<id>.yml
#   2026-05-03 => exemplar tier
#   2026-06-22 => new tier (pending review)
```

14 of the 42 cite external literature (their YAML contains a `cite-`
token); those, plus the 29 new glosses, are the set flagged for
author review.

## Files

- `_schema.yml` — schema documentation: every permitted top-level
  field with an example. Read this first if you're authoring a new
  concept. (Underscore-prefixed, so the tools skip it.)
- `_candidates.txt` — auto-discovered concept candidates in
  `BufferStockTheory.md` (emitted by `tools/concepts_discover.py`).
  Each row is `id <TAB> line <TAB> kind <TAB> co-occurring-ids <TAB>
  context`.
- `_review-status.yml` — per-concept domain-expert review state
  (underscore-prefixed; see "Review status").
- `<id>.yml` — one authored concept. The id must equal the filename
  stem.

> **Naming rule:** any helper file in this directory that is *not* an
> authored concept **must** be underscore-prefixed. Both
> `tools/concepts_validate.py` and `tools/concepts_render.py` treat
> `concepts/*.yml` as the concept set and skip `_`-prefixed files. A
> non-underscore helper (e.g. naming the review file `review-status.yml`)
> would be picked up as a concept and **break validation**.

## Workflow: author → validate → render

```
python3 tools/concepts_discover.py    # refresh _candidates.txt from the paper
python3 tools/concepts_validate.py    # lint every concepts/<id>.yml (skips _*)
python3 tools/concepts_render.py      # (re)write _ai/concepts/<id>.md (skips _*)
python3 tools/concepts_freshness.py   # assert YAML count == index.md count
```

`concepts_validate.py` is the one you'll run most. It checks every
required field, dereferences every `defining_equation.anchor` and
`sources[*].anchor` against the paper, confirms every
`relations[*].target` either names another concept file or an existing
paper anchor, and rejects cycles in the `implies` / `special-case-of`
graphs.

**`_ai/concepts/*.md` are RENDERED views — do not hand-edit them.**
They are regenerated wholesale by `tools/concepts_render.py` from the
YAML; any manual edit will be silently overwritten on the next render.
`_ai/concepts/index.md` (header: "N concept(s) authored.") is likewise
generated, and is what `concepts_freshness.py` checks against.

## Anchors: two tiers

Concept `sources[*].anchor` and `defining_equation.anchor` values
resolve through a registry of paper anchors. There are two registries,
a mechanical superset and a curated subset:

- **`anchor-registry.{yml,json}`** — *all 343 resolvable anchors* in
  the paper (every labelled equation, section, figure, theorem, etc.),
  generated mechanically by `tools/anchor_registry.py`. Per-object
  truth table via `tools/anchor_audit.py`. This is the universe an
  anchor *can* point at.
- **`object-registry.{yml,json}`** — the curated subset of ~40
  **in-scope named scholarly objects** (theorems, lemmas,
  propositions, definitions, assumptions, properties, remarks, plus
  the atlas-referenced named equations) that actually belong in the
  concept graph. Generated by `tools/object_registry.py` by filtering
  the 343 anchors down to the named scholarly tier. This is the set a
  concept *should* normally anchor to.

## DDSL bridge (reserved / deferred)

Every concept carries a `bellman_ddsl:` field:

```yaml
bellman_ddsl:
  perch: '(deferred)'
  stage: '(deferred)'
```

This is a **reserved, fully deferred** bridge to the DDSL
(perch/stage) Bellman formalism. It is **not delivered** for any of
the 42 concepts — all are placeholder `(deferred)`. Do not represent
the atlas as having a working DDSL correspondence.

## RAG indexing policy (Option C — external, deferred)

Indexing policy decided this session: **index BOTH the source
`concepts/*.yml` AND the rendered `_ai/concepts/*.md`**, each tagged by
`artifact_kind` (`concept_yaml` / `concept_rendered`); the indexer must
avoid unweighted duplicate retrieval of the two views of the same
concept.

Caveats:
- The actual RAG index is **out-of-repo** (the `matsya` droplet,
  running branch `main`). This README documents policy; it does not
  rebuild anything.
- The in-repo half is the `.ragignore` edit. As of this session `_ai/`
  is still excluded there; flipping it to *included* (the Option C
  change) plus the external index rebuild and the before/after
  benchmark re-run are **deferred** (owner declined the rebuild this
  session). The current droplet index does not yet honor even the
  existing `.ragignore`.

## Adding a concept

1. Find the candidate in `_candidates.txt`. Note its line number and
   the co-occurring concept ids (the auto-bootstrap signal for
   relations). If it names a scholarly object, confirm it appears in
   `object-registry.yml`.
2. Read the corresponding paragraph in `BufferStockTheory.md` and the
   surrounding `prf:assumption` / `prf:theorem` blocks. The paper is
   the ground truth; the concept is interpretation layered on top.
3. Copy `_schema.yml` to `concepts/<id>.yml` and fill in the fields.
   The id must equal the filename stem. Leave `bellman_ddsl` as the
   `(deferred)` placeholder.
4. `python3 tools/concepts_validate.py` must pass (anchors resolve, no
   relation cycles).
5. `python3 tools/concepts_render.py` to (re)generate the rendered
   page; `python3 tools/concepts_freshness.py` to confirm counts agree.
6. Add the new id to `concepts/_review-status.yml` as `pending`.
